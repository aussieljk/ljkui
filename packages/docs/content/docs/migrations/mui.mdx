---
title: From MUI
description: Incrementally move from MUI's theme and sx model to ljkui.
---

Migrate by feature area rather than attempting a package-wide replacement. Both libraries support a provider-style
theme, but ljkui favors semantic component props, CSS variables, and ordinary class names over `sx`.

## Theme

```diff
- <ThemeProvider theme={theme}>
+ <Theme accentColor="blue" grayColor="neutral">
    <App />
- </ThemeProvider>
+ </Theme>
```

## Components

```diff
- <Button variant="contained" color="primary">Save</Button>
+ <Button variant="solid" color="accent">Save</Button>
```

## Styling

Move reusable visual decisions into the ljkui theme or application CSS. Keep one-off layout in `className` or
`style`; prefer component props for supported sizes, colors, and variants.

## Suggested order

1. Typography, buttons, badges, and progress indicators
2. Inputs and field composition
3. Navigation
4. Dialogs, menus, and other overlays
5. Tables and application-specific composites

Run both providers temporarily if needed, but avoid nesting resets around the same screen for longer than the
transition requires.
